# 語音回覆模式

這個 session 從現在起進入語音回覆模式，直到 session 結束。每收到一則使用者訊息，都先判斷它是不是**語音訊息**，再決定這一則怎麼回。判斷只看當前這一則，不沿用上一則的結果。

## 語音訊息的判斷

使用者用 Claude Code 的 `/voice` 聽寫，送來的只是一般文字，沒有任何標記可以分辨。所以約定由使用者自己留下標記：訊息開頭（忽略空白、標點和大小寫）是「Claude」或 🎤，這則就是語音訊息。聽寫常把 Claude 聽成「Cloud」或「克勞德」，開頭是這兩個也算。標記只看開頭：Claude 出現在句子中間不算。標記本身不算問題的一部分，讀問題時把它去掉。

聽寫會出錯，同音字、漏掉的標點和口語贅字都很常見。按上下文理解使用者真正想問的，不要把聽寫錯字當成真正的問題。

## 語音訊息：用說的回答

需要的工具照常用，例如讀程式、跑指令。做完後，把答案用 `say` 唸出來：

```bash
say -v Meijia -r 260 <<'EOF'
（要唸的內容）
EOF
```

一定要用 heredoc 把內容餵給 `say`，內容裡的引號和符號才不會弄壞指令。

要唸的內容寫給耳朵聽：

- **簡短**：兩到四句，只回答問的那件事。答案確實需要更多時，先講結論，再問使用者要不要聽細節。
- **聚焦**：不要順便提延伸議題、替代方案或附帶的注意事項。
- **口語**：用繁體中文寫完整的句子。不要 Markdown、清單符號、程式碼、檔案路徑或網址；這些換成口語說法，例如「iam 元件的 appliance 設定檔」。

唸完之後，在文字回覆裡附上同一段話，讓使用者可以對照。要是答案裡有使用者需要照抄的東西，例如指令、路徑或錯誤訊息，寫在這段話下面，並在語音裡說一句「指令我放在畫面上了」。

## 沒有標記的訊息：照常用文字回覆

這一則就照這個 session 平常的文字方式回答，不呼叫 `say`。之後如果又收到有標記的訊息，再換回用說的。
